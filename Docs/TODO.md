退避的实际间隔只有单元测试；失败任务的详情页没在真机上见过（这轮没有任务失败）。
⭐ **M2R4 真机上抓到一个网关 bug 并已修**（`03d0077`）：取消排队任务后 worker 又取消一次，
非法转移抛异常、日志里刷 traceback。原测试没把流程走到底、也不看日志。

⬜ **「生成视频」按钮再点时要确认 —— 用户 2026-09-28 定的需求**：
提交成功后按钮**仍然可以再点**，但点下去时如果**已有任务正在跑**，弹一个确认：
「现在已有任务正在跑，是否添加到队列？」—— 选「是」就提交（排进队列），选「否」就什么都不做。
- 理由：再提交一次可能是想要的（换个随机 seed 再来），也可能是误触、白付一次 GPU。
- ⚠️ **「已有任务正在跑」要问网关，不能只看 App 本地**：App 可能刚重启、任务可能是别的入口提交的。
  做法倾向：点击时查一次 `GET /v1/jobs`，有非终态任务就弹确认。
  ⚠️ **查询失败时怎么办要在开工时定**（倾向：照样弹确认并说明「没问到队列状态」，不要默默直接提交）。
- 没有任务在跑时直接提交，不弹确认。
- 放在哪一轮：**没排**。它只动 App，倾向随 M2R5 一起做；开工时定。

⭐ **M2R2 修了两个网关 bug**：
① 假图片（扩展名对、内容不是图）被静默接受成 0×0 的 asset ——
ffprobe 对坏文件退出码是 0，守卫只挡「宽高缺失」挡不住「宽高是 0」。
后果会推迟到提交生成任务时才崩（除以零）。
② 慢接口的标量超时同时设了连接与读，导致 ComfyUI 挂掉时上传要等 60 秒，
**造成一次误诊**（App 说「服务器没有应答」而网关其实好好的）。

⭐ **M2R1 顺带修了一个网关的 bug**：`/v1/health` 在 ComfyUI 挂掉时**永远不返回** ——
httpx 里请求级的 `timeout=None` 意思是「不设超时」而不是「用默认值」。
`queue()` 也中招，那条更严重（它在任务轮询循环里）。已修并补了回归测试。

⭐ **视觉不设独立里程碑**（2026-09-23 决定，需求 §7.1.5）。拆成两块：
**视觉基础**（配色、字号层级、间距、圆角、状态色）放 **M2R1**，写一次全 App 继承；
**逐页打磨**跟着各自的页面走，**每一轮做出来的页面在那一轮里就要打磨到能看**。
⚠️ 「最后设一个 UI 美化里程碑」是最差的选项：UI 代码写两遍，
而且要在一次改动里同时动七八个页面 —— 而 UI 只能靠人眼判，那时没法定位是哪一处改坏的。

⚠️ **App 的自动化测试能覆盖的东西比网关少得多。** 网关那边 workflow 构造、
帧数换算、状态机都是纯逻辑，开发机上就能测；
**App 这边真正的风险（播放、上传、网络分支）全都必须上真机** ——
所以每一轮的判据都落在真机上，`./gradlew test` 只是入场券。

### 挡住 M3（媒体库）

- ⬜ **⚠️ `job_id` 的序号在网关重启后会重复**：序号是进程内的，
  重启后从 `0001` 重来，同一天重启两次就会产生两个相同的 `job_id`。
  M1 状态不持久化、重启后旧 id 本来也查不到，所以现在影响为零 ——
  但**做持久化时必须先解决它**，否则会撞主键。
- ⬜ **任务与媒体的元数据存哪**：SQLite 还是 JSON 索引文件。
  倾向 SQLite（要分页和按来源过滤）。
- ⬜ **缩略图什么时候生成**：任务结束时顺手做，还是首次访问时懒生成。
  倾向前者，那时文件刚写完、磁盘缓存还热。
- ⬜ **任务状态持久化**：M1 只存内存，网关一重启就丢。

### 挡住 M4（接入 SD）
