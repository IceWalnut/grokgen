## 3. 下一轮（M2）要验证的假设

**手机上到底播不播得动。**

这是 M1 退出标准里唯一没达成的那条。网关侧已经准备好：
`GET /v1/jobs/{id}/video` 支持 Range，响应头里有 `Accept-Ranges: bytes`
（播放器靠它决定要不要让用户拖进度条）。

**进度怎么推给 App 已经定了：App 轮询，网关不向 App 推送**（2026-09-23）。
依据是采样只有 8 步（约每 9 秒一个进度更新），而 2 秒一次的轮询在 75 秒里
能问到约 37 次 —— **推送没有多出来的信息可以给**；且只有一个用户，并发压力为零。
记在契约 §6.1 与 App 架构文档 §1。

⚠️ **但那只决定了「网关 → App」这一段。「网关 → ComfyUI」那一段仍然要做** ——
`stage`（现在是加载模型还是采样）与 `progress` 的数据**只能**来自 ComfyUI 的
WebSocket 事件，网关现有的 `/queue` 与 `/history/{id}` 都回答不了「跑到第几步」。
不连它，这两个字段永远是空的，而需求 F2 点名要求单独显示分钟级的 `loading_model`。
⚠️ **「ComfyUI 没有别的 HTTP 途径拿进度」这一点还没核实**，动手前先确认一次。

## 4. 会咬人的坑

按「多久会撞上」排。

### 4.00 ⚠️ Android 默认拦掉明文 HTTP（**M2R1 必定撞上**）

网关是 **HTTP 不是 HTTPS**（信任边界是整个 tailnet），
而 Android 从 API 28 起**默认禁止明文 HTTP 流量**。

⇒ 要配 `network_security_config.xml`，**只对后端那个域名放开明文**，
不要开全局 `usesCleartextTraffic="true"` —— 全局开等于把 App 发往任何地址的
明文请求都放行了，而只有 tailnet 内那一个是可信的。

⚠️ **这一条同时影响接口调用和视频播放** —— Media3 的 HTTP 数据源走同一套策略。

### 4.001 ⚠️⚠️ WSL 镜像网络：关闭端口上的连接是**被丢弃**，不是被拒绝

**这是 M2R1 里两个问题的共同根因，会再咬人。**

正常情况下连一个关着的端口会立刻收到 ECONNREFUSED。
这台服务器的 WSL 用镜像网络，**包被直接丢掉**，于是调用方一直等到超时。
实测：ComfyUI 停掉后从服务器本机 curl `127.0.0.1:8188`，10 秒超时，不是秒拒。

两个后果：

1. **网关的 `/v1/health` 曾经永远不返回** —— 因为 `_get_json` 把 `timeout=None`
   传给 httpx，而那表示「不设超时」不是「用默认值」。平时看不出来是因为
   正常环境下连接会秒拒。已修（`c9b0873`），但**这类写法要警惕**。
2. **App 分不开「服务器离线」和「网关没起来」** —— 两者都只表现为连接超时。
   需求 F1 那一条已按实测改成合并一档。

⇒ **凡是「连不上会怎样」的推断，在这台机器上都要实测，不能按常识推。**

### 4.002 ⚠️ `pkill -f` / `pgrep -f` 会匹配到自己的命令行

```bash
ssh server "pkill -f 'python main.py --listen 0.0.0.0'"
```

远端跑这条命令的 shell，**它自己的命令行里就含着那个模式串** ——
pkill 把自己的父 shell 一起杀了，命令没有任何输出，看起来像什么都没发生。

⇒ **先 `pgrep` 取 PID 再 `kill`，模式要避开自身**
（例如用 `bin/uvicorn` 而不是完整的 `uvicorn app.main:app`）。

M2R1 踩过一次：以为网关停了、实际没停，白跑了一轮真机验证。

### 4.0 跑网关的测试必须 `cd server`，不能在仓库根目录跑

`asyncio_mode = "auto"` 写在 `server/pyproject.toml` 里，
从根目录跑 pytest 读不到它，所有裸 `async def` 测试都报
`async def functions are not natively supported`。

实测：根目录跑有一批**假失败**，`server/` 目录跑才是全绿（当前 145 条）。
**那 10 条是假失败**，很容易被当成真回归去查。

### 4.005 ⚠️ 契约里先写下、实现还没跟上的**字段**，会被静默吞掉

pydantic 默认把没声明的字段**直接丢掉，不报错**。

所以往契约的**已有请求体**里加一个「M-x 才实现」的字段之后，
App 一旦开始传它：请求通过、任务成功、结果生成，**只是那个字段没起作用**，
而且哪里都不报错。

实测过一次：`loras` 字段加进契约后，传一个非空值进去照样返回 200。
现在改成明确拒绝（422，并说清为什么）。

⇒ **以后再往契约里加「以后才实现」的字段，必须同时加一道拒绝的守卫。**

⚠️ **新增的路径不用管**（调不到会 404，失败是可见的）。
**只有加在已有请求体里的字段有这个问题** —— 这是两者的关键区别。

### 4.01 ⚠️ ComfyUI 的 `completed` 字段不是「结束了」的意思

**它的含义是「成功完成」。** 被中断或报错的任务是：

```
status_str = "error"    completed = False
```

M1R7 冒烟实测到的。用 `completed` 判断「这次执行结束了没有」，
**被中断和报错的任务就永远等不到终态** —— 而任务超时默认是关的，即无限轮询。

⇒ 判断执行是否结束用 `JobRecord.finished`（白名单 `{success, error}`），
不要用 `completed`。

⚠️ **更该记住的是这个 bug 为什么没被测出来**：`FakeComfyClient` 把失败写成了
`completed=True`，**替身与真实行为不符**，于是 145 条离线测试全绿。
**替身写错时，它保护的不是代码，是那个 bug。**

### 4.05 归一化只能做一次，否则 seed 会对不上

`normalize()` 在用户没填 seed 时会**随机生成**一个，
而 `build_workflow()` 内部会调 `normalize()`。

所以**不能**「提交时算一次回给 App，执行时再算一次喂给 ComfyUI」——
两个 seed 不一样，任务照样成功、视频照样出来，
只是用户拿回报的 seed **永远复现不出那个视频**，**而且不报错**。

现在的做法：探测首帧尺寸与建图都在 `POST /v1/jobs` 里做完，
结果存在 Job 上带着走。VS-18 守这条。

### 4.1 开发机的代理会把 Tailscale 请求变成 502

本机 shell 里有 `http_proxy=127.0.0.1:7890`，而 `no_proxy` 里没有 tailnet 域名。
`curl http://icewalnut-1060.tail22a711.ts.net:8188/...` 会返回 **502**，
**看起来像服务器挂了，实际服务器好好的**。

⇒ 从开发机发的每一条 curl 都要带 `--noproxy '*'`。（runbook §6.4）

⚠️ **这个坑只存在于开发机的 shell 里，手机上没有。**
**不要在 App 里为它写任何绕过逻辑。**

### 4.2 不要在服务器上改代码

服务器上 `~/workspace/grokgen` 是 `origin/main` 的只读检出，
部署脚本用 `git reset --hard`，**改了下次部署就没了**。
要调试就改本仓库 → 提交 → 推送 → 重新部署。

### 4.3 跑 GPU 验证前先看 ComfyUI 忙不忙

```bash
curl -s --noproxy '*' http://icewalnut-1060.tail22a711.ts.net:8188/queue
```

排队等别人跑完，比自己插进去更省时间。

### 4.31 ⚠️ 「模型加载是分钟级」这个说法要分两种情况（M1R7 实测更正）

文档里多处写着「模型加载是分钟级的固定开销」。实测之后要拆开看：

| 情况 | 一次 5 秒视频的总耗时 | 实测过吗 |
|---|---|---|
| 模型已在显存（热） | **75 秒** | ✅ M1R7 |
| 显存被清空、ComfyUI 进程还在 | **94 秒**（多付约 19 秒） | ✅ M1R7 |
| **ComfyUI 进程重启后的第一次** | **92 秒** | ✅ **M2R1** |

⇒ **三种情况几乎一样贵，「分钟级」那个说法是错的。**

⭐ **M2R1 实测更正**：以前一直以为进程重启后那一次会是分钟级 ——
理由是要从磁盘读约 29 GB 模型（主模型 14 GB + text encoder 15 GB），
而服务器只有 31 GB 内存装不下。**实测 92 秒，比 `/free` 之后那次（94 秒）还略快。**

测量条件比 M1R7 那次更彻底：**WSL 发行版刚被 `wsl --shutdown` 关掉再起来**，
所以页面缓存也是空的（`ram_free` 31.7 GB / 33.5 GB），是真正的冷盘读。

⚠️ **另有一笔要分开算**：ComfyUI 进程从启动到 8188 端口能应答，**要 66 秒**。
那 66 秒发生在提交任务之前，上面那 92 秒不含它。
所以「从什么都没有到拿到第一个视频」大约是 **66 + 92 ≈ 158 秒**。

⇒ **对 M4 的显存切换设计**：`/free` 和重启进程的代价基本相同，
所以不必为了省那点时间去坚持用 `/free` —— 但**重启要多付端口就绪的 66 秒**，
这才是两者真正的差别。

⚠️ 每种情况**都只跑了 1 次**。测量条件：4080 SUPER、736x416 / 124 帧 / 8 步 Turbo。
M2R1 那次是 T2VA，M1R7 那两次是带首帧图的，**严格说不是同一个输入**。

### 4.4 三个数值约束，写错了不会报错

| 约束 | 值 | 写错的后果 |
|---|---|---|
| 分辨率 | **必须是 32 的倍数** | 节点直接拒绝 |
| 帧数 | **17k+5 的格子**（5, 22, 39 … 124 …） | 会被静默取整，实际时长和用户填的不一样 |
| 对齐指令行的秒数 | 用**换算后**的实际时长（5 秒 → `5.17`） | **不会报错**，只是模型把尾帧对到错的时间点 |

⚠️ 需求文档 §8.2 里建议的 `768x432` **在网关这条路上无效**（432 不是 32 的倍数）。
M1 用 `736x416`，那是服务器上已有成品的真实分辨率。

### 4.5 首帧是拉伸，尾帧是居中裁剪

原生节点里 `first_frame` 用 `crop="disabled"`（直接拉伸），
`last_frame` 用 `crop="center"`。**首帧宽高比不匹配时会变形，不是裁剪。**

### 4.6 装 Python 包：两台机器的做法不一样

**服务器**：代理变量指向 `127.0.0.1:7890`，而那个端口**没有进程监听**。
`pip install` 必须摘掉代理并走镜像 —— `scripts/deploy_server.sh` 已经处理好了，
手工在那边装包时要记得同样处理。

**开发机**：代理是活的，但**缺 `python3.10-venv`**（`ensurepip` 不存在，装它要 sudo）。
所以开发机建 venv 用 `~/.local/bin/uv`：

```bash
cd server && uv venv .venv --python 3.10
uv pip install --python .venv/bin/python -r requirements.txt
```

⚠️ 两端建 venv 的工具不同（uv vs `python3 -m venv`），这是一处已知的不对称。

### 4.7 ⚠️ WSL 端口连不上时，先分清是两种坑里的哪一种

M1R3 中途撞到过：8188 / 2222 / 7869 从外面全连不上，但 Windows 的 22 正常。
**不是 WSL 被回收**（发行版当时已经跑了 1 天 3 小时），
而是 Hyper-V 防火墙只放行环回、不放行外部入站。

判别方法与处置见 runbook §6.5。**已加规则恢复，但可能再次发生。**

### 4.8 用户实际在用的模板不在 ComfyUI 目录里

`Docs/knowledge/DasiwaMinimaxH3WorkflowsT2VA_cMMH3V23.json` 是**第一手依据**
（采样 profile、对齐指令行写法、`N/A` 规则都来自它）。
它原本只在 Windows 的 `E:\Downloads\minimax-h3\`，已拷进仓库。
ComfyUI 自带的 V13/V16 是**不同的版本**，别拿它们当准。

### 4.9 WSL 会自己停下来

Windows 那侧有个计划任务按住它。网关是常驻服务，
**它活着的前提是 WSL 发行版没被回收**。连不上时先查那个任务。（runbook §4）
