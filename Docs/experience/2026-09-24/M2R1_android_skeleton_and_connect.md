## 1. 本轮最重要的结果：在真机上抓到一个网关的 bug

**而且 149 条离线测试全绿，一条都没抓到它。**

### 现象

按计划停掉 ComfyUI、网关留着，期望 `/v1/health` 在 2 秒内返回
`comfy.reachable = false`。实际是**永远不返回** —— 从开发机打 15 秒超时，
从服务器本机打 20 秒超时。

`/v1/jobs` 和 `/docs` 都是毫秒级返回，所以网关进程是好的，卡的只有调 ComfyUI 那一步。

### 根因

`server/app/comfy/http_client.py` 的 `_get_json`：

```python
response = await self._client.get(path, timeout=timeout)   # timeout 是 None
```

**httpx 里请求级的 `timeout=None` 意思是「不设超时」，不是「用客户端默认值」** ——
它把构造器里那 2 秒显式覆盖掉了。表示「用默认」要用 `httpx.USE_CLIENT_DEFAULT`。

在服务器上实测过三种写法，不是凭印象：

| 写法 | 结果 |
|---|---|
| `timeout=None`（原代码） | 跑满 12 秒仍未返回 |
| 不传 timeout 参数 | 2.00 秒后抛 `ConnectTimeout` |
| `httpx.USE_CLIENT_DEFAULT` | 2.00 秒后抛 `ConnectTimeout` |

### 为什么以前一直没暴露

**因为它需要两个条件同时成立。**

连本机的关闭端口，正常会立刻收到 ECONNREFUSED —— 有没有超时都一样快。
但**这台服务器的 WSL 用镜像网络，关闭端口上的连接是被丢弃而不是被拒绝**：
从服务器本机 curl `127.0.0.1:8188` 实测 10 秒超时，不是秒拒。

于是「没有超时」在这台机器上变成了真的永远等下去。

### 影响两处，第二处更严重

1. `/v1/health` 在 ComfyUI 挂掉时永远不返回 —— **而那正是这个接口存在的意义**
2. **`queue()` 跑在任务轮询循环里** —— ComfyUI 跑到一半挂掉，网关会永远轮询下去

第二条是 M1R7 修过的那种「无限轮询」，只是换了一条路进去。

### 为什么离线测试没抓到

`FakeComfyClient` 是**立刻抛异常**的，替身根本走不到超时那条路。

⚠️ **这和 M1R7 那个 `completed` 字段是同一类问题** ——
替身与真实行为不符时，它保护的不是代码，是那个 bug。
**M1R7 记过这条教训，本轮又以另一种形式撞上了一次。**

### 修法与验证

`_get_json` 里把 `None` 翻译成 `httpx.USE_CLIENT_DEFAULT`。
补了三条回归测试，打在**真实客户端**上（用 `httpx.MockTransport` 抓请求，
断言它携带的 connect 超时等于配置值），**不用会立刻抛异常的替身**。

⚠️ 撤掉修复复跑，其中两条确实变红，报 `assert None == 2.0` —— 正好点名了 bug。

部署后实测：ComfyUI 停着时 `/v1/health` **2.038 秒返回 200**，带着原因。

## 2. 第二个被实测推翻的结论：需求 F1 有一条做不到

### 要求

需求 F1 要求把「服务器离线」和「网关进程没起来」分别提示。

### 实测

判别本来靠「连接被拒绝」和「连接超时」的区别。**同一个网络行为让它失效**：

| 制造的情况 | 结果 |
|---|---|
| 杀掉网关进程，WSL 与 Windows 都留着 | 连接超时 |
| `wsl --shutdown` 之后 | 连接超时 |

两种表现完全一样。

⚠️ **第一版文案就犯了这个错**：网关明明是被我杀掉的，App 却显示
「连不上那台服务器」——**把用户指向了错误的方向**。

### 处置

按 `Docs/Validation.md` §4.1，**改上游文档，不改判据**：

- 需求 F1：那两条标成「分不开」，写清为什么
- App 架构新增 §5.0 记录这件事
- 代码：合并成一档 `NoAnswer`，文案把三种可能都列出来，
  并告诉用户下一步该去看什么

`ConnectionRefused` 那一档保留（换个不用镜像网络的环境它就会出现），
但**至今没有被真实触发过，按 §3 规则 ③ 不算验证过**。

## 3. 补上一个挂了很久的欠账：冷启动 92 秒

TODO 里「ComfyUI 进程重启后第一次生成要多久」挂了两轮。本轮顺手量到了。

**结果推翻了「模型加载是分钟级」这个长期说法。**

| 情况 | 一次 5 秒视频 | 测于 |
|---|---|---|
| 模型已在显存（热） | 75 秒 | M1R7 |
| `/free` 清空显存后 | 94 秒 | M1R7 |
| **ComfyUI 进程重启后** | **92 秒** | **M2R1** |

⭐ 测量条件比 M1R7 更彻底：**WSL 刚被 `wsl --shutdown` 关掉再起来**，
页面缓存也是空的（`ram_free` 31.7 GB / 33.5 GB），是真正的冷盘读。
产物 ffprobe 验过：h264 + aac、736×416、124 帧、5.167 秒、1.05 MB，是一次完整生成。

⚠️ **另有一笔要分开算**：ComfyUI 从启动到 8188 能应答**要 66 秒**，
那 66 秒在提交任务之前，不含在 92 秒里。

⇒ **对 M4 的显存切换设计**：`/free` 与重启进程的**生成耗时基本相同**，
真正的差别是重启要多付 66 秒的端口就绪时间。

⚠️ 每种情况都只跑了 1 次；M2R1 这次是 T2VA，M1R7 那两次带首帧图，
**严格说不是同一个输入**。

## 4. 计划里的三个风险，一次构建全部落地

| 风险 | 结果 |
|---|---|
| R1 AGP 8.13.2 与 Gradle 8.14.5 不兼容 | **没发生** |
| R2 根工程直接当 Android 模块，AGP 不接受 | **没发生** —— 不用建 `app/app/`，文档里那些路径不用改 |
| R5 依赖版本组合冲突 | **兑现了**，见下 |

**R5 的具体表现**：最新的 AndroidX 要 AGP 9.1.0+ 和 compileSdk 37，
报错点名了 `compose.ui:1.12.1` 与 `lifecycle:2.11.0`。

**处置**：退回一组相容的版本（compose-bom 2026.06.01 → compose ui 1.11.4），
**不升 AGP 大版本**。理由写进了 `libs.versions.toml`：
M2R1 要回答的是「手机能不能连上网关」，不是「用不用最新工具链」。

⚠️ 这条决定意味着**将来有一次单独的工具链升级要做**，不是免费的。

## 7. 两个操作上的坑，记下来免得再踩

### 7.1 `pkill -f` / `pgrep -f` 会匹配到自己

```bash
ssh server "pkill -f 'python main.py --listen 0.0.0.0'"
```

ssh 远端跑这条命令的那个 shell，**它自己的命令行里就含着那个模式串** ——
于是 pkill 把自己的父 shell 也杀了，命令没有任何输出，
看起来像「什么都没发生」。

⇒ **先 `pgrep` 取 PID 再 `kill`，而且模式要避开自身**
（用 `bin/uvicorn` 而不是完整的 `uvicorn app.main:app`）。

本轮因为这个坑，有一次以为网关停了、实际没停，白跑了一轮真机验证。

### 7.2 用 adb 点按钮要先确认坐标

`input keyevent 111`（ESC）在这台手机上触发的是系统设置搜索，不是收起键盘。
点错一次会把 App 顶到后台，后面的截图全是错的。

⇒ **每次点之前先截一张图确认布局**，不要沿用上一次的坐标 ——
键盘弹出会让整页上移。
